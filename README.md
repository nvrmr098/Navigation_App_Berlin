# Berlin Route (Android)

A WebView-based Android app that makes the Berlin S-Bahn and U-Bahn easier to understand for newcomers.
Everything runs offline: the map, search and route finding are bundled in the app.

## What it does

- **Map** (left tab): one combined S-Bahn and U-Bahn map, own drawing, with a filter (S + U, S-Bahn only, U-Bahn only), pan and zoom, station search with suggestions, tap a station for its lines.
- **Navigate** (middle tab): start and destination fields with a suggestion list, swap button, fastest route and a "fewer changes" alternative, step list with line, direction and stops, share, recent trips and favorites.
- **Start**: a short intro shows each line of the route appearing with arrows, a marker runs along the route, then live navigation begins. 2D is the default; the 3D button switches to a generic city with identical buildings (S-Bahn elevated, U-Bahn underground).
- **More** (right tab): favorites, recent trips, service updates (placeholder), ticket zones, dark mode, step-free option (placeholder), language (placeholder), share, feedback, privacy, about and data credits.

## Project layout

- `web/`: the interface, written in React with Vite (`web/src`)
  - `App.jsx`: state, pages, navigation mode and the animation loop
  - `pages.jsx`, `ui.jsx`: Navigate page, More page, search box, badges
  - `mapEngine.js`: canvas map (drawing, labels, pan and zoom)
  - `scene3d.js`: 3D view (three.js, loaded only when you tap 3D)
  - `route.js`: routing engine (Dijkstra, boarding waits, transfer times)
  - `data.json`: generated network data (310 stations, 24 lines)
- `app/`: the Android shell (Kotlin WebView). `app/src/main/assets/www/` is the built web app and is generated by `npm run build`; do not edit it by hand.

## Working on the interface

    cd web
    npm install
    npm run dev       # live preview in the browser
    npm run build     # writes the app into app/src/main/assets/www

Run `npm run build` before building the APK in Android Studio. The GitHub workflow does this automatically.

## Regenerating the data

`scripts/build_data.py` builds `data.js` from the npm packages `vbb-lines`, `vbb-stations` and `vbb-line-colors`:

    python3 -I scripts/build_data.py <folder with the extracted npm packages> web/src/data.json

Source data: VBB Verkehrsverbund Berlin-Brandenburg GmbH via daten.berlin.de, licence CC BY 3.0. The credit text is in the app (More > About) and must stay.

## Build

Android Studio (recommended): open this folder, let Gradle sync, press Run, or
Build > Build App Bundle(s) / APK(s) > Build APK(s).

Command line (needs JDK 17+ and the Android SDK; create the wrapper once with `gradle wrapper`):

    ./gradlew assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
    ./gradlew bundleRelease        # AAB for Google Play (needs a signing key)

The workflow in `.github/workflows/build-apk.yml` builds a debug APK on GitHub.

## Before you publish

- Change `applicationId` in `app/build.gradle.kts` (it can never change after the first upload).
- Check Google Play's current target API level requirement and raise `targetSdk` if needed.
- Sign the release build (Play App Signing with an upload key).
- Add a privacy policy page (required by Play).
- Do not use BVG or S-Bahn Berlin logos or their official map design.

## Known limits

- Travel times are estimates (distance, average speeds, typical waits), not a live timetable. Real timetable routing (GTFS with RAPTOR) and live delays from the VBB interface are the next step.
- Lines S4 and S45 are not in the source data. U4 was added by hand.
- Lines are straight segments between stations (geographic with a spread-out centre). A fully hand-drawn 45 degree layout would be easier to read and is a good next design step.
- Bus and tram are not included yet.
- The 3D view is generic: boxes for buildings and trains, no real landmarks.
- Step-free routing, language switch and service updates are placeholders.
- This project was written without access to the Android SDK, so it has not been compiled here. If Gradle reports a version problem, update the plugin versions in the root `build.gradle.kts`.


## Version 0.4: live GPS, real 3D, new design

- **Live navigation with GPS**: tap Start, choose "Live navigation with GPS". The app follows your position along the route, announces the next stop, warns when you leave the route and offers a reroute. Without GPS (for example in a tunnel) it continues with a timetable estimate. Choose "Demo ride" to preview without moving.
- **Real 3D city**: the 3D view uses MapLibre with OpenFreeMap (real OpenStreetMap buildings). It needs internet. Offline it falls back to a simple generic 3D city.
- **Modern UI**: glass surfaces, floating dock, bottom sheets, automatic light and dark theme.
- **Permissions**: location (only while the app is open) and vibration. Your position never leaves the device.
- **Credits**: OpenFreeMap, OpenMapTiles, OpenStreetMap contributors (ODbL), VBB open data (CC BY 3.0).
- Test GPS on a real device. Browser previews need https for location (GitHub Pages is https).

## Change tips (carriage and platform position)

For many transfers the route steps show where to ride and where to wait on the platform. The data comes from the crowd sourced dataset vbb-change-positions (ODbL 1.0, https://github.com/juliuste/vbb-change-positions). It covers about 83 percent of the real transfer pairs in this network. Where no data exists, no tip is shown.

Regenerate after the dataset changes:

    npm i vbb-change-positions   (in a scratch folder)
    python3 -I scripts/build_changes.py <scratch>/node_modules/vbb-change-positions/data.ndjson web/src/data.json web/src/changes.json

Station exits are not included yet (VBB entrance coordinates are a possible next step).
